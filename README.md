# WEB-Laboratories

Учебный проект по веб-разработке: две последовательные лабораторные на одной модели студента общежития. Интерфейс оформлен по мотивам ИСУ ИТМО; это **не официальный сервис ИТМО**.

За основу ЛР 1 взята актуальная локальная версия проекта [Lab-1](https://github.com/Nikilireous/Lab-1). Во второй работе сохранены её поля и пользовательские сценарии.

| Работа | Что сделано | Где читать отчёт |
| --- | --- | --- |
| [ЛР 1](lab1/) | Три страницы на HTML/CSS/JavaScript, проверка формы, поиск, создание, изменение и удаление. Данные хранятся в cookie браузера. | [Отчёт ЛР 1](reports/Lab1.md) |
| [ЛР 2](lab2/) | Тот же интерфейс и модель студента, но данные и правила перенесены в Django REST Framework; добавлены серверные фильтры и JSON-хранилище. | [Отчёт ЛР 2](reports/Lab2.md) |

## Быстрый запуск

### ЛР 1

```bash
cd lab1
python3 -m http.server 8000
```

Откройте `http://localhost:8000/`. При дальнейшей работе используйте тот же хост: cookie на `localhost` и `127.0.0.1` различаются.

### ЛР 2

```bash
cd lab2
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py runserver 127.0.0.1:8001
```

Откройте `http://127.0.0.1:8001/`. API доступен по `/api/requests`; полный список методов и примеры находятся в [инструкции ЛР 2](lab2/README.md). База данных и миграции не требуются. Для проверки выполните `python manage.py check` и `python manage.py test requests_api`.

## Как связаны работы

Во второй лабораторной сохранены поля и сценарии первой. Главная перемена — место хранения и обработки данных: в ЛР 1 браузер работает с cookie, в ЛР 2 браузер отправляет запросы Django, а сервер хранит записи в JSON-файле. Записи из старых cookie не появляются в серверном файле автоматически.

Отчёты написаны как материал для самостоятельной защиты: в них есть модель данных, назначение файлов, ход типового запроса, сценарий демонстрации и краткие ответы на вопросы. История Git разделена коммитами с пометками `ЛР1` и `ЛР2`.

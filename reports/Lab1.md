# Отчёт по лабораторной работе № 1

## Тема и цель

Клиентское веб-приложение для учёта студентов, связанных с заселением в общежитие. Цель работы — создать страницы для просмотра, добавления, редактирования и удаления записей, проверить вводимые данные и сохранять записи в браузере.

Сверка с официальным заданием «Лабораторная 1.pdf», стр. 1: приложение сделано без фреймворков, использует CSS и отдельные файлы JavaScript для логики. В нём есть таблица студентов, форма добавления и редактирования, досье, проверка полей средствами HTML и JavaScript, адаптивные стили и хранение в cookie — одном из разрешённых вариантов. Обязательная иконка вкладки в виде кота находится в `lab1/favicon/app.svg`.

## Используемые технологии

- **HTML** задаёт структуру трёх страниц.
- **CSS** оформляет таблицу, форму, профиль и адаптивное отображение на узком экране.
- **JavaScript** выполняет проверку формы, поиск, операции с записями и работу с cookie.
- **SVG** используется для favicon: белый кот на синем фоне, чтобы учебный интерфейс сохранял выбранную цветовую гамму.

Для первой лабораторной не нужны серверная бизнес-логика и внешние библиотеки. Все действия с данными выполняются в браузере; для удобного открытия страниц достаточно простого сервера статических файлов.

## Модель студента

| Поле | Смысл и правило ввода |
| --- | --- |
| `fullName` | Фамилия и имя, при необходимости отчество. Минимум два слова; буквы русского или латинского алфавита, пробелы и дефисы; не более 120 символов. |
| `group` | Код группы: заглавная латинская буква и четыре цифры. Первая цифра от 1 до 4, вторая от 1 до 5. Например, `M3301`. |
| `isuId` | Уникальный идентификатор студента: шесть цифр, первая не ноль. Например, `262144`. |
| `dormitory` | Номер общежития от 1 до 20. |
| `room` | Номер комнаты от 100 до 599. |
| `settlementDate` | Дата заселения от текущего дня до одного календарного месяца вперёд. |
| `isForeign` | Признак иностранного студента: `true` или `false`. |
| `notes` | Необязательная заметка длиной до 500 символов. |

ИСУ ID служит ключом записи. При редактировании он отображается только для чтения, поэтому ссылка на профиль и поиск записи остаются однозначными.

## Страницы и функции

### Список студентов — `index.html`

На главной странице показана таблица студентов с ФИО, группой, ИСУ ID, номером общежития и датой заселения. Над таблицей отображаются количество студентов в списке и количество иностранных студентов. Когда записей нет, показано сообщение и кнопка добавления.

Поле поиска фильтрует видимые строки сразу при вводе. Поиск не зависит от регистра и проверяет ФИО, группу и ИСУ ID. Число найденных записей показано под таблицей. Из строки можно открыть профиль, перейти к редактированию или удалить запись. Для удаления требуется второе нажатие в течение трёх секунд.

### Форма — `student-form.html`

Одна форма используется для добавления и редактирования. При открытии ссылки с параметром `id` форма загружает соответствующего студента из cookie и заполняет поля. Без параметра `id` открывается пустая форма добавления.

Обязательные поля проверяются средствами HTML и функцией `validateStudent()` в JavaScript. Функция приводит текст к удобному виду, проверяет значения и возвращает ошибки по полям. После успешного сохранения открывается список и показывается уведомление. Счётчик возле заметки показывает оставшееся число символов.

### Профиль — `student-profile.html`

Профиль открывается по ссылке с ИСУ ID в параметре `id`. Страница показывает основные данные, статус иностранного студента, дату заселения и заметку, если она заполнена. Здесь же доступны редактирование и удаление. При неправильном ID выводится сообщение «Студент не найден».

## Сохранение данных в cookie

Каждая запись хранится как JSON в отдельной cookie с именем `student_dormitory_<ИСУ ID>`. Перед записью JSON кодируется для cookie. Время хранения — один год; cookie доступна по пути `/` и использует `SameSite=Lax`.

`getStudents()` читает cookie студентов и превращает их обратно в JavaScript-объекты. `saveStudents()` сохраняет текущий список, удаляет cookie удалённых студентов и проверяет, что браузер действительно сохранил запись. ИСУ ID проверяется на уникальность до добавления. Код также умеет прочитать данные из старой общей cookie `students_dormitory`, если отдельные cookie ещё не созданы.

Cookie привязаны к хосту сайта и браузеру. Поэтому записи, созданные на `localhost`, не появятся автоматически при открытии через `127.0.0.1`, в другом браузере или после очистки cookie.

## Как запустить и показать работу

Откройте папку `lab1` через простой локальный веб-сервер и перейдите на `index.html`. Например, из папки `lab1` выполните `python3 -m http.server 8000`, затем откройте `http://localhost:8000/`. Один и тот же хост следует использовать на протяжении демонстрации, поскольку cookie привязаны к нему.

Порядок демонстрации:

1. Добавить студента с допустимыми значениями полей.
2. Показать новую строку, статистику и поиск по части ФИО или ИСУ ID.
3. Открыть профиль и проверить отображение всех сохранённых данных.
4. Изменить группу или заметку и убедиться, что изменения видны в профиле и списке.
5. Попробовать добавить запись с тем же ИСУ ID и показать сообщение об ошибке.
6. Удалить студента вторым нажатием на кнопку удаления.
7. Обновить страницу: сохранённые записи остаются, поскольку они находятся в cookie.

## Проверка

Синтаксис всех JavaScript-файлов проверен командой `node --check`: ошибок нет. Для ручной проверки удобно пройти сценарий выше, отдельно проверить неверные ФИО, группу, ИСУ ID, числа и дату. Браузер может сам заблокировать отправку некорректного обязательного поля до вызова JavaScript-проверки.

## Ответы на вопросы к защите из задания (стр. 2)

1. **Что такое HTML и для чего нужны элементы и атрибуты?** HTML описывает содержимое страницы. Например, `<table>` задаёт таблицу студентов, `<form>` — форму, `<input>` — поле ввода. Атрибуты уточняют поведение: `type="number"` задаёт числовое поле, `required` делает его обязательным, `id` позволяет найти элемент из JavaScript.

2. **Как устроены HTML-страница и DOM?** У каждой страницы есть `<!DOCTYPE html>`, `<html>`, `<head>` с заголовком и подключением CSS, а также `<body>` с видимым содержимым. Браузер превращает разметку в дерево объектов DOM. Скрипты получают узлы через `document.getElementById()` и меняют их содержимое.

3. **Как работают формы и валидация?** В `student-form.html` используются текстовые, числовые, календарное поле, флажок и `textarea`. Атрибуты `required`, `pattern`, `min`, `max` и `maxlength` выполняют первую проверку. `js/validation.js` дополнительно проверяет данные перед сохранением, а `js/form.js` показывает ошибки возле полей.

4. **Что такое CSS, селекторы и каскад?** CSS задаёт внешний вид HTML. Селектор выбирает элементы: `.btn` — по классу, `#notes-counter` — по ID, `.nav-link.active` — по двум классам. Если подходит несколько правил, браузер учитывает их приоритет и порядок. В `css/style.css` общие правила расположены раньше правил для узких экранов.

5. **Что такое адаптивная вёрстка?** Это изменение расположения элементов под доступную ширину. В `css/style.css` применяются `flex`, `grid` и медиазапросы: боковое меню становится верхним, поля формы выстраиваются в один столбец, а строки таблицы на телефоне показываются карточками.

6. **Для чего нужен JavaScript в клиентском приложении?** Он выполняется в браузере и реагирует на действия пользователя. Здесь JavaScript загружает записи из cookie, фильтрует список, проверяет форму и обновляет страницы после добавления, изменения или удаления студента.

7. **Какие конструкции и типы JavaScript используются?** ФИО и ИСУ ID хранятся как строки, номера общежития и комнаты — как числа, `isForeign` — как логическое значение. Один студент представлен объектом, список — массивом. В коде используются функции, условия `if`, циклы и методы массивов `filter`, `find`, `some`.

8. **Как работает событийная модель браузера?** Обработчик запускается после события. `DOMContentLoaded` начинает работу страницы, `input` обновляет поиск и счётчик заметки, `submit` проверяет форму, `click` обрабатывает действия. Для кнопок в таблице один обработчик поставлен на `tbody`: событие от кнопки доходит до него через всплытие.

9. **Как JavaScript меняет DOM?** `js/app.js` создаёт строки таблицы и добавляет их в `<tbody>`, меняет счётчики через `textContent` и скрывает или показывает пустое состояние через `hidden`. `js/profile.js` заполняет досье значениями выбранного студента. Пользовательские строки экранируются перед вставкой в HTML таблицы.

10. **Какие есть способы хранения на стороне клиента?** `localStorage` хранит строки для сайта, cookie — небольшие пары «имя–значение», IndexedDB подходит для более сложных и объёмных данных. В этой работе выбран разрешённый заданием вариант cookie: каждый студент хранится отдельно, а содержимое записи представляет собой JSON.

11. **Что такое JSON?** Это текстовый формат обмена и хранения данных. `JSON.stringify(student)` превращает объект студента в строку перед записью в cookie; `JSON.parse(...)` восстанавливает объект при чтении. При повреждённой записи приложение её пропускает.

12. **Что такое CRUD и где он реализован?** CRUD — создание, чтение, обновление и удаление. В `js/student-service.js` этому соответствуют `addStudent()`, `getStudents()` / `findStudentByIsuId()`, `updateStudent()` и `deleteStudent()`. ИСУ ID используется как ключ; перед добавлением проверяется, что такого ID ещё нет.

13. **Как организованы файлы приложения?** Три HTML-страницы отвечают за список, форму и досье. Общие стили находятся в `css/style.css`. Файлы в `js/` разделены по задачам: cookie, операции со студентами, проверка и поведение каждой страницы. Назначение файлов перечислено в таблице выше.

14. **Как разделены интерфейс и бизнес-логика?** HTML описывает элементы, которые видит пользователь. `js/app.js`, `form.js` и `profile.js` управляют отображением и событиями. `js/validation.js` содержит правила проверки, `js/student-service.js` — операции с записями, `js/cookies.js` — прямую работу с cookie.

15. **Как использовать инструменты разработчика для отладки?** На вкладке Elements можно проверить разметку и действующие CSS-правила, в режиме адаптивного экрана — ширины телефона и ноутбука. Console показывает ошибки скриптов. В Application → Cookies можно увидеть сохранённые записи, а после изменения или удаления студента проверить, как меняются cookie. Перезагрузка страницы показывает, что данные сохранились.

# Отчёт по лабораторной работе № 1

## Тема и цель

Клиентское веб-приложение для учёта студентов, связанных с заселением в общежитие. Цель работы — создать страницы для просмотра, добавления, редактирования и удаления записей, проверить вводимые данные и сохранять записи в браузере.

Этот отчёт описывает фактически реализованную первую лабораторную. Текст задания № 1 отсутствует среди доступных материалов, поэтому формулировки здесь не выдаются за дословные требования преподавателя.

## Используемые технологии

- **HTML** задаёт структуру трёх страниц.
- **CSS** оформляет таблицу, форму, профиль и адаптивное отображение на узком экране.
- **JavaScript** выполняет проверку формы, поиск, операции с записями и работу с cookie.

Для первой лабораторной не нужны серверная бизнес-логика и внешние библиотеки. Все действия с данными выполняются в браузере; для удобного открытия страниц достаточно простого сервера статических файлов.

## Модель студента

| Поле | Смысл и правило ввода |
| --- | --- |
| `fullName` | Фамилия и имя, при необходимости отчество. Минимум два слова; буквы русского или латинского алфавита, пробелы и дефисы; не более 120 символов. |
| `group` | Код группы: заглавная латинская буква и четыре цифры. Первая цифра от 1 до 4, вторая от 1 до 5. Например, `M3301`. |
| `isuId` | Уникальный идентификатор студента: шесть цифр, первая не ноль. Например, `262144`. |
| `dormitory` | Номер общежития от 1 до 20. |
| `room` | Номер комнаты от 100 до 599. |
| `settlementDate` | Дата заселения от текущего дня до одного календарного месяца вперёд. |
| `isForeign` | Признак иностранного студента: `true` или `false`. |
| `notes` | Необязательная заметка длиной до 500 символов. |

ИСУ ID служит ключом записи. При редактировании он отображается только для чтения, поэтому ссылка на профиль и поиск записи остаются однозначными.

## Страницы и функции

### Список студентов — `index.html`

На главной странице показана таблица студентов с ФИО, группой, ИСУ ID, номером общежития и датой заселения. Над таблицей отображаются количество студентов в списке и количество иностранных студентов. Когда записей нет, показано сообщение и кнопка добавления.

Поле поиска фильтрует видимые строки сразу при вводе. Поиск не зависит от регистра и проверяет ФИО, группу и ИСУ ID. Число найденных записей показано под таблицей. Из строки можно открыть профиль, перейти к редактированию или удалить запись. Для удаления требуется второе нажатие в течение трёх секунд.

### Форма — `student-form.html`

Одна форма используется для добавления и редактирования. При открытии ссылки с параметром `id` форма загружает соответствующего студента из cookie и заполняет поля. Без параметра `id` открывается пустая форма добавления.

Обязательные поля проверяются средствами HTML и функцией `validateStudent()` в JavaScript. Функция приводит текст к удобному виду, проверяет значения и возвращает ошибки по полям. После успешного сохранения открывается список и показывается уведомление. Счётчик возле заметки показывает оставшееся число символов.

### Профиль — `student-profile.html`

Профиль открывается по ссылке с ИСУ ID в параметре `id`. Страница показывает основные данные, статус иностранного студента, дату заселения и заметку, если она заполнена. Здесь же доступны редактирование и удаление. При неправильном ID выводится сообщение «Студент не найден».

## Сохранение данных в cookie

Каждая запись хранится как JSON в отдельной cookie с именем `student_dormitory_<ИСУ ID>`. Перед записью JSON кодируется для cookie. Время хранения — один год; cookie доступна по пути `/` и использует `SameSite=Lax`.

`getStudents()` читает cookie студентов и превращает их обратно в JavaScript-объекты. `saveStudents()` сохраняет текущий список, удаляет cookie удалённых студентов и проверяет, что браузер действительно сохранил запись. ИСУ ID проверяется на уникальность до добавления. Код также умеет прочитать данные из старой общей cookie `students_dormitory`, если отдельные cookie ещё не созданы.

Cookie привязаны к хосту сайта и браузеру. Поэтому записи, созданные на `localhost`, не появятся автоматически при открытии через `127.0.0.1`, в другом браузере или после очистки cookie.

| `js/cookies.js` | Простые операции чтения, записи и удаления cookie. |
| `js/student-service.js` | Получение списка и операции добавления, изменения, удаления и поиска студента по ИСУ ID. |

| `js/profile.js` | Отображение профиля и действия с текущей записью. |

## Как запустить и показать работу

Откройте папку `lab1` через простой локальный веб-сервер и перейдите на `index.html`. Например, из папки `lab1` выполните `python3 -m http.server 8000`, затем откройте `http://localhost:8000/`. Один и тот же хост следует использовать на протяжении демонстрации, поскольку cookie привязаны к нему.

Порядок демонстрации:

1. Добавить студента с допустимыми значениями полей.
2. Показать новую строку, статистику и поиск по части ФИО или ИСУ ID.
3. Открыть профиль и проверить отображение всех сохранённых данных.
4. Изменить группу или заметку и убедиться, что изменения видны в профиле и списке.
5. Попробовать добавить запись с тем же ИСУ ID и показать сообщение об ошибке.
6. Удалить студента вторым нажатием на кнопку удаления.
7. Обновить страницу: сохранённые записи остаются, поскольку они находятся в cookie.

## Проверка

Синтаксис всех JavaScript-файлов проверен командой `node --check`: ошибок нет. Для ручной проверки удобно пройти сценарий выше, отдельно проверить неверные ФИО, группу, ИСУ ID, числа и дату. Браузер может сам заблокировать отправку некорректного обязательного поля до вызова JavaScript-проверки.

## Краткие ответы для защиты

**Почему ИСУ ID уникален?** Он используется как ключ записи, в ссылках на профиль и редактирование. Перед созданием приложение ищет такой ID среди сохранённых студентов и отклоняет дубликат.

**Где хранятся данные?** В cookie браузера, по одной JSON-записи на студента. Это клиентское хранение: у первой лабораторной нет сервера данных.

**Как работает поиск?** После каждого ввода приложение получает список студентов и оставляет записи, у которых запрос содержится в ФИО, группе или ИСУ ID. Сравнение ФИО и группы выполняется без учёта регистра.

**Как устроена проверка?** HTML задаёт обязательные поля и простые ограничения. JavaScript дополнительно нормализует значения и проверяет формат, диапазоны и реальность даты. Ошибки показываются рядом с полями.

**Зачем отдельные файлы JavaScript?** Каждый отвечает за одну понятную часть работы: cookie, операции с данными, проверку формы или конкретную страницу. Это упрощает поиск и объяснение кода.

**Чем отличается лабораторная № 2?** Там интерфейс обращается к API на Django REST Framework, а хранение и бизнес-логика перенесены на сервер. Первая лабораторная полностью работает на стороне браузера.
